ARCHITECTURE & PROTOCOL

Engineered for Throughput & Safety

STORAGE

Linux io_uring & Share-Delete Safety

Uses native tokio-uring asynchronous disk I/O on Linux, Windows FILE_SHARE_DELETE handles so files stay movable/deletable, and crash-safe atomic fastresume flushes.

NETWORKING

Dual-Stack TCP, QUIC & UPnP

Single-port dual-stack IPv4/IPv6 listeners, HTTP/UDP multi-tracker announce-list, Kademlia DHT (BEP 5/32), PEX (BEP 11), UPnP mapping, and TorTor-to-TorTor QUIC.

INTEGRITY

Dynamic SIMD & Hardened Parser

Every piece is verified via SHA-1 before commit, file paths are sanitized against traversal, and bencode payloads enforce strict size and nesting bounds.

CONTROL

4-Tab Settings & Live Tuning

Adjust bandwidth caps, active peers per torrent, global inbound cap, upload slots, block pipeline depth, timeouts, PEX/QUIC toggles, and compact UI density.

SELECTIVE I/O

Live Multi-File Selection

Choose which files inside a torrent to download even mid-swarm. Unselected files are never created on disk and skipped at piece level.

SCALING & I18N

DPI, TextScaleFactor & RU/EN UI

Proportional layout scaling across Windows, Linux, and macOS Retina displays using bundled Onest typography and fluent translations.

Built on Open-Source Rust Foundations: TorTor + Hey

TorTor is crafted by Vitaly Golik (mjojo) at GLK Dev as a showcase of clean systems programming paired with our own lightweight Rust GUI framework — Hey.

  • Hey GUI Engine: pure-Rust declarative MVU framework without Chromium/Electron memory overhead (~19 MB binary).
  • End-to-end Rust stack: custom BitTorrent protocol engine, DHT, trackers, UPnP, and GPU rendering in one cohesive codebase.
